Pipeline review

Deterministic Go rules find the blockers. The model explains and prioritizes them. No project data changes until the configured project owner approves them.

The name is recorded on every decision, and only the configured project owner can approve changes. A decision without a name is refused by the API and by the tracker.

      Agent review

      The ADK agent reads the status, explains the blockers and proposes at most one dry-run update. It has no tool that can change the project, so a change is only ever a proposal here, recorded in the audit trail.

        Proposed updates

        Every proposal carries the tracker version it was built against. The tracker re-checks it when you decide, so a project that moved is refused instead of overwritten.

        Propose an update myself

        Allowed fields: owner_id (a project team member), status, due_date (YYYY-MM-DD), progress_percent, blocked_reason (only on a blocked milestone).
